1. **책 경계 붙음 64건**

2. **절 번호 없는 이어짐 줄 45건**

   - 예:
     ```

     창35:야곱의 <야곱의 아들들(대상 2:1-2)> 아들은 열둘이라
     ```
   - 앞 절 본문 뒤에 공백으로 이어 붙여야 한다. f1은 이 꼬리들이 잘려 있었다.
3. **시편 권 구분 표시 4건** — `시42:제이권`, `시73:제삼권`, `시90:제사권`, `시107:제오권`. 절이 아니므로 버린다.

## 4. 변환 스크립트

- 경로: `scripts/rebuild-bible-json.js` (의존성 없음, Node 내장 모듈만 사용)
- 상태: `npx eslint scripts/rebuild-bible-json.js` 통과.
  - 프로젝트의 `babel-eslint@8` + ESLint 6 조합이 `for...of`를 오탐(unused var)해서 **index 기반 for 루프로 작성**했다. `for...of`로 되돌리면 lint가 깨진다.
- 주요 규칙:
  1. f1의 책/장/절 배열 길이와 책 약어·이름을 그대로 유지
  2. f1 절 문자열의 선행 `<...>` 제목 보존
  3. f1 절이 `null`이고 제목이 없으면 원문의 선행 제목 사용
  4. 원문 본문에 붙은 `<...>` 제목은 제거
  5. 합절은 첫 절에 전체 본문, 나머지 절은 `''`
  6. 절 번호 없는 이어짐 줄은 앞 절에 병합
  7. 붙어 있는 책 첫 절(`...고전1:1`)을 분리
  8. 행 24:7은 `(없음)`
- 사용법:
  ```bash
  # 신명기 6장 예시(JSON)
  node scripts/rebuild-bible-json.js --book deut --chapter 6 --pretty

  # 전체 변환 파일 생성
  node scripts/rebuild-bible-json.js --out src/assets/ko_rev.json
  ```
- 기타 옵션: `--f1 <path>`, `--src <path>`, `--book <abbrev>`, `--chapter <n>`, `--pretty`, `--help`.
- 통계는 stderr로 출력된다.

1. 사용자에게 f1 덮어쓰기 여부와 13개 빈 절/15개 제목 처리 방침 확인.
2. 필요하면 `--include-source-headings` 옵션 구현(제목을 절 앞으로 이동할지, 원문 위치 그대로 둘지 결정).
3. `node scripts/rebuild-bible-json.js --out src/assets/ko_rev.json` 실행.
4. `sw.js` 캐시 버전 v5 → v6 갱신.
5. `npm run build:dev` 또는 `npm start`로 실행해 신 6장, 시 92편, 롬 9장, 행 24장 화면 확인.
6. 필요 시 이슈 #1에 결과 댓글.
7. 사용자가 요청할 때만 커밋/PR 생성.

## 12. 주의사항

- 원문 파일은 CP949이므로 `iconv` 없이 Node에서 읽을 때 반드시 `new TextDecoder('euc-kr')`를 쓸 것. `cp949`는 Node에서 미지원.
- 책 이름 정규식은 **길이 내림차순**으로 만들어야 한다. 그렇지 않으면 `전`이 `고전/살전/딤전/벧전`을 잘못 자른다.
- f1 제목은 항상 절 문자열 맨 앞에만 있다. 원문의 절 중간 제목과 혼동하지 말 것.
- `src/assets/ko_rev.json`은 앱 번들에 포함되므로 데이터 교체 후 서비스워커 캐시 버전을 반드시 올려야 한다.
- 개역개정4판은 대한성서공회 저작물이다. 원문 파일은 사용자가 제공했으며, 배포/라이선스 검토가 필요하면 별도 확인할 것.
